## Defect and boundary

During the 2026-10-19 Human Edge Guest review of the Japanese Ashen Crown Quadrant, Enter and Space selected an Entity, but the focus ring disappeared, the page sometimes moved upward, and the next Tab reached the brand. The Human observed the Space case without a screenshot action between activation and focus loss. This remains Human Browser Evidence for the original source, not post-fix acceptance.

Source audit and a controlled real-module DOM integration probe identified the focus-loss sequence: keyboard-style point click updates selection and restores focus to the replacement point; asynchronous browser-local Workspace save then settles and rerenders the whole application, removing that focused node without restoring the currently focused control. The earlier automated test covered the immediate focus call but not the later save settlement. The direct cause of the reported upward browser scroll is not established; the save-result rerender previously had no document-scroll restoration.

## Correction

Save success, refusal, and coordination-error rendering now capture the **current** focus target and document scroll immediately before the save-result render. If the render detaches the focused control, it restores only the corresponding still-enabled, non-inert control with the same DOM path and identifying attributes, without scrolling it into view. A later user move to another point, label, or Header control therefore takes precedence over the point that initiated the save. If rendering deliberately focuses a dialog, that focus and its scroll behavior are left alone. The latest document position is restored only when the render loses focus, so scrolling during a delayed save is not reset to the earlier activation position.

Keyboard-style activation of a Quadrant label also restores focus to that label immediately after the selection render. The existing separate point and label Tab stops, native button activation, arrow-key Assessment editing, pointer drag/selection, and context menu remain in place. Selection does not call Assessment value mutation.

## Human-adopted selection and focus color separation — 2026-10-20

The Human adopted orange for Entity selection and the blue/purple outline for keyboard focus. Focus or hover alone must not make an unselected Entity appear selected. This is a visual decision; the separate point/label Tab stops, selection actions, 30px point hit target, Assessment editing, and Workspace behavior remain unchanged.

The earlier `.plot-item:focus-within` rule colored the full 30px unselected point hit target orange, while a later selected-point rule cleared that large background and shadow. The CSS-only correction removes that inherited orange hit-target treatment. An unselected point keeps a blue dot and gets only a blue halo on hover/focus plus its focus-visible outline when keyboard focused. A selected point keeps its orange dot and small halo with or without focus, and adds the same blue/purple outline only while keyboard focused. Unselected labels use a blue-tinted hover/focus-within treatment; selected labels retain the existing orange-tinted treatment. A transient non-selected drag halo is blue, so it does not imply selection before the drag ends.

In a fresh isolated headless Edge profile at `http://127.0.0.1:5517/`, the Japanese Ashen Crown sample plotted ten Entities on Command Authority / Combat Capability. Browser-native Tab and computed styles confirmed the four point states: no orange for unselected/unfocused or unselected/focused, orange for selected/unfocused and selected/focused, and a solid 2px outline only on the keyboard-focused point. The point hit target remained 30 × 30 CSS pixels. Pointer hover on an unselected point produced a blue halo and blue-tinted label, without orange. Tab/Shift+Tab transferred the outline between the point and its separate label; an unselected focused label had a blue tint and its own outline, while a selected label retained the orange tint. Space selected Garrick and Enter selected Selene. After the local save settled, focus and document scroll position stayed at their observed values, and the stored Dataset JSON was string-identical to its pre-selection value. Tab to a label after selection left the selection orange and removed the point outline. These are **Codex Browser Evidence**, not Human Browser Acceptance; this follow-up did not capture an additional screenshot.
